### Inherited from WP-19 — all three closed or answered

#### D-1 — P2 — a cold start after a kill resumed the legacy Séance, not the open journey — **FIXED**

*Location:* `web-frontend/pages/_app.tsx` (the native resume redirect),
`lib/pilot-resilience.ts` (`pilot:resume:v1`).
*Reproduction (WP-19, iPhone 16 simulator):* start the V2 journey, kill the app mid-scene,
relaunch. Three times out of three.
*Actual:* the app opened the **legacy** exercise Séance. `readResumeActivity()` returns the
single stored activity, and only `pages/atelier.tsx` ever wrote one — for an unfinished
legacy practice session. The journey wrote nothing, so the older activity always won.
*Expected:* while the envelope is enabled and a journey for today is still open, the
journey is where a cold start lands.

**Fix.** A new `web-frontend/lib/journey-resume.ts` holds the whole rule:
`useDailyJourney` writes a `pilot:journey-resume:v1` mark whenever the envelope is enabled
and the journey's status is `preparing`/`active`/`paused`, and clears it otherwise;
`resolveResumeHref()` returns that mark's href when it is fresh and open, and otherwise
falls through to `readResumeActivity()` **unchanged**. `_app.tsx` calls the resolver
instead of the reader. `pages/atelier.tsx` gained a small `?view=journey` handler
(guarded on `journeyEnabled`, marked `WP-20`, outside Codex's `SessionView` branch) so the
redirect lands *inside* the scene rather than on Home.

Deliberate limits, so nobody has to rediscover them:

* A `completed`, `ended_early` or `unavailable` journey never wins — "resume your scene"
  after the scene is over is the same lie WP-19 §5 already refused for the morning push.
* A mark older than 48 h is discarded, so yesterday's kill does not hijack today.
* The href is a constant; a corrupt, foreign or absolute value is refused, never navigated
  to.
* The mark lives under `pilot:`, so the existing sign-out sweep (`clearPilotResilience`)
  already clears it and a second account cannot inherit the first one's target.

*Verification.* `web-frontend/lib/journey-resume.test.js` — 11 cases, wired into
`package.json` and CI as `test:resume-target`. Plus a live browser check on the harness: a
fresh learner who starts the journey has
`pilot:journey-resume:v1 = {"journeyId":"81bb0157-…","localDate":"2026-09-07","status":"active","href":"/atelier?view=journey",…}`
and no legacy activity; the learner whose journey is finished has the mark **absent** and
only the legacy activity, which is the fallback path. Navigating to `/atelier?view=journey`
opens the scene at the step it was left on.
*Not verified here:* the redirect itself only runs on `isNativePlatform()`, so the
end-to-end kill-and-relaunch proof needs the simulator again — that is WP-19's §6 walk to
re-run, and it is listed as pending in §7.

#### D-2 — P3 — the WKWebView ignores iOS Dynamic Type — **ANSWERED, no setting exists**

*Location:* `web-frontend/capacitor.config.ts`, `ios/App/App/capacitor.config.json`,
`styles/globals.css:236`.
*Reproduction (WP-19):* `simctl ui … content_size accessibility-large` → no visible change.

**There is no Capacitor or WKWebView preference that makes a web view follow Dynamic
Type.** Capacitor 8.4.0's iOS config surface, read from
`node_modules/@capacitor/cli/dist/declarations.d.ts`, is exactly: `path`, `scheme`,
`overrideUserAgent`, `appendUserAgent`, `backgroundColor`, `zoomEnabled`, `contentInset`,
`scrollEnabled`, `cordovaLinkerFlags`, `allowsLinkPreview`, `loggingBehavior`,
`includePlugins`, `limitsNavigationsToAppBoundDomains`, `preferredContentMode`,
`handleApplicationNotifications`, `webContentsDebuggingEnabled`, `initialFocus`,
`buildOptions`. None of them concerns text size. The only web mechanism WebKit offers is
CSS (`font: -apple-system-body` plus a `text-size-adjust` other than `100%`), and this app
pins its rem base explicitly — `:root[data-font-size]` is `14.5 / 16 / 19px` and
`html { -webkit-text-size-adjust: 100% }` — so the OS could not move it even if the CSS
opted in. Nothing to add "without native code beyond a line"; documented instead.

**The remediation WP-19 asked for already ships.** Réglages → Apparence → «Corps du texte»
(Petit / Moyen / Grand) is exactly the in-app text-size control, and it moves the whole
rem-based `--t-*` scale by −9 % / +19 %. It was exercised in this walk and it works.

*Recommendation, not applied here:* `zoomEnabled` is unset, so it defaults to **false** —
pinch-zoom is off in the native shell. Combined with Dynamic Type being ignored, the in-app
control is a learner's *only* text-size channel. Setting `ios: { zoomEnabled: true }` in
`capacitor.config.ts` is a one-line change and a genuine accessibility improvement, but it
changes native gesture and viewport behaviour that cannot be judged from a browser, so it
belongs to the native owner with a device in hand. Recorded, not made.

#### D-8 — **WITHDRAWN** — "the journey's Pause control has no visible focus indicator"

Filed, then disproved by re-testing, and kept here because the *reason* it was wrong is a
trap the next tester will fall into too.

The matrix driver measured the focus ring by calling `element.focus()` and reading the
computed style. That reports `outline-style: none` on **every** av2 control, because
`:focus-visible` deliberately does not match programmatic focus — it needs a real keyboard
interaction. Re-run with genuine `Input.dispatchKeyEvent` Tab presses over the journey
scene, every control matched `:focus-visible` and drew the design's ring:

```
Quitter la lecture  fr-icon-btn  :focus-visible ✓  outline: solid 3px rgb(245,239,225)
Panneau             fr-word      :focus-visible ✓  outline: solid 2px rgb(245,239,225)
```

The rule is `.av2 :focus-visible { outline: 3px solid var(--av2-focus); outline-offset: 2px }`
(`styles/atelier-v2.css:335`) and it covers the whole system. Tab order was checked at the
same time and follows DOM order, which matches visual order. **Any future focus-ring
measurement must use dispatched key events, never `.focus()`.**

#### D-15 — P2 — the grammar fiche overflows horizontally at 320 px with large text

*Location:* `/grammar?concept=1` (the Cahier fiche), 320 px viewport, root font-size
raised to 24 px — i.e. a small phone with Réglages → «Corps du texte» → Grand.
*Actual:* `documentElement.scrollWidth = 338` against `clientWidth = 320`. One `DIV`
spans `[16, 322]` and pushes the page 18 px wide; the whole screen scrolls sideways.
*Expected:* the shell is width-bound, not type-bound — the same promise
`styles/globals.css` makes in its own comment about the 14.5/16/19 px scale ("still short
of a reflow … the phone shell is width-, not type-, bound"). This is the one place that
promise breaks.
*Evidence:* `cahier-fiche-320-largetext.png`, `walk-findings-320-largetext.json`. It is
the only overflow in 105 route captures; the same page is clean at 320 px default text and
at 390 px large text.

*Reproduction:* any authenticated route at 320 or 390 px.
*Actual:* a 36 × 36 button (below the 44 × 44 minimum) drawn in the pre-av2 language — a

### Not defects — checked and dismissed

* **The mixed English/French chrome on the journey card and inside the scene** ("Today",
  "Start today", "Step 1 of 3") is the contract's `control_language`, which is `en` for a
  learner whose `native_language` is English. French is the target-language content; the
  control language is deliberate.
* **"Something you did has not reached the server yet."** appearing after typing without
  sending is correct: the draft is genuinely unsent, and the banner is WP-10's honest
  pending state, not a failure claim. It cleared on submit.
* **`/notebook?tab=releve` showing the Règles tab** — the Cahier's parameter is `mode`,
  not `tab` (`notebookModeFromQuery`); `/notebook?mode=releve` opens Le Relevé correctly.
  A tester's error, corrected in the walk, recorded so the next one does not re-file it.
* **The inline word-help buttons at 22 px tall** in the scene reader — inline targets
  within a sentence, exempt under WCAG 2.5.8, and the reader's whole word-help affordance
  depends on them.
